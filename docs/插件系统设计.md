# TermOne 插件系统设计

> 版本：v1（草案） ｜ 日期：2026-10-23
> 目标：把 SFTP、AI 辅助等增值能力从主窗口剥离，主窗口只保留「轻量实用」的核心，插件按需安装、按需加载。
> 形态决策：**前端插件为主**（JS/TS 包，动态 `import()` 懒加载，零新增原生依赖）。
> 配套：`docs/需求.md`（定位与红线） ｜ `docs/竞品分析与需求规划.md`（编号与排期）

---

## 1. 设计原则

| 原则 | 含义 |
|---|---|
| **核心最小** | 主窗口 = 终端 + 会话 + 档案 + 同步 + 插件运行时。多余一行都不放。 |
| **按需加载** | 插件默认不启用；启用后也只在真正用到时才 `import()`。 |
| **零原生依赖** | 插件不得引入 Rust 动态库或新的原生依赖，保证跨平台免编译分发。 |
| **能力在核心，UI 在插件** | 涉密 / 高频 / 需要系统权限的后端 IPC 命令留在核心（如 SFTP 的 6 个命令），插件只写 UI 与交互。插件迭代**无需重编 Rust**。 |
| **崩溃隔离** | 单个插件崩溃不影响主窗口与正在运行的会话。 |
| **最小权限** | 插件声明权限，越权即拒；密钥环永久不可访问。 |

## 2. 总体架构

```
┌──────────────────────────────────────────────────────────┐
│                     插件（JS/TS 包）                        │
│   manifest (termone.plugin.json) + index.js (ESM)          │
│   activate(ctx) → 注册面板/命令/设置；deactivate() 注销      │
└───────────────────────┬──────────────────────────────────┘
                        │ Host API v1（受限）
┌───────────────────────▼──────────────────────────────────┐
│                 插件运行时（核心，前端）                     │
│  registry  注册/注销面板、命令、设置项、状态栏项              │
│  loader    动态 import()、错误边界、超时                     │
│  manager   安装/启用/停用/更新/卸载，持久化到 plugins 表      │
│  sandbox   权限校验、IPC 白名单、域名白名单                  │
└───────────────────────┬──────────────────────────────────┘
                        │ Tauri IPC（白名单）
┌───────────────────────▼──────────────────────────────────┐
│              核心后端（Rust / term-core）                   │
│  会话、档案、同步、密钥环（永不对插件开放）                   │
│  已暴露命令：sftp_list / sftp_mkdir / sftp_remove /         │
│  sftp_rename / sftp_download / sftp_upload /               │
│  local_list / local_mkdir / session_log_read …             │
└──────────────────────────────────────────────────────────┘
```

## 3. 插件清单 `termone.plugin.json`

```jsonc
{
  "id": "com.termone.sftp",            // 全局唯一，反域名
  "name": "SFTP 文件管理",
  "version": "0.1.0",
  "main": "index.js",                  // 相对包根的 ESM 入口
  "minHost": "0.2.0",                  // 最低宿主版本
  "maxHost": null,                     // 可选：上限
  "author": "TermOne",
  "description": "远端/本地双栏文件管理，支持上传下载与传输队列",
  "icon": "icon.svg",
  "official": true,                    // 官方插件：免风险提示
  "license": "MIT",
  // 权限声明：安装时展示给用户确认
  "permissions": [
    "ipc.sftp_list", "ipc.sftp_mkdir", "ipc.sftp_remove",
    "ipc.sftp_rename", "ipc.sftp_download", "ipc.sftp_upload",
    "ipc.local_list", "ipc.local_mkdir",
    "ui.panel", "ui.command", "ui.toast",
    "storage.local"
  ],
  // 静态贡献点：安装后即可在 UI 中看到，激活后才真正渲染
  "contributes": {
    "panels": [
      { "id": "sftp", "title": "文件", "side": "right", "icon": "folder" }
    ],
    "commands": [
      { "id": "sftp.open", "title": "打开 SFTP 面板", "shortcut": "Alt+Shift+F" }
    ],
    "settings": [
      { "id": "sftp.showHidden", "title": "显示隐藏文件", "type": "boolean", "default": false }
    ]
  }
}
```

**校验规则（安装时强制）**：
- `id` 符合 `^[a-z0-9]+(\.[a-z0-9-]+)+$` 且未冲突；
- `version` 符合 SemVer；`main` 存在；
- `minHost` ≤ 当前宿主版本；
- `permissions` 全部为已知枚举（未知项直接拒绝安装）；
- 官方插件校验内置签名，第三方插件安装时弹出风险提示。

## 4. 插件生命周期

| 阶段 | 触发 | 行为 |
|---|---|---|
| **安装** | 市场一键 / 导入 `.tpk` / 开发者模式 | 校验 manifest → 解压到 `<app_data>/plugins/<id>/` → 写入 `plugins` 表 → 状态 `installed, disabled` |
| **启用** | 用户在插件管理中打开开关 | 状态置 `enabled`，登记静态贡献点（面板/命令出现在 UI） |
| **激活** | 首次真正用到（打开面板 / 执行命令） | `import()` 入口 → 调 `activate(ctx)` → 渲染内容 |
| **停用** | 关闭开关 | 调 `deactivate()` → 注销全部贡献点与订阅 → 从模块缓存释放 |
| **更新** | 市场检测到新版本 | 先 `deactivate` → 替换文件 → 重新 `activate` |
| **卸载** | 用户确认 | `deactivate` → 删除目录与 `plugins` 记录 → 清理插件私有存储 |

**插件模块接口**：

```ts
export interface PluginModule {
  activate(ctx: PluginContext): void | Promise<void>;
  deactivate(): void | Promise<void>;
}
export interface PluginContext {
  readonly manifest: PluginManifest;
  readonly host: HostApi;
  readonly subscriptions: Disposable[]; // 运行时统一回收
}
```

## 5. Host API v1

插件**只能**通过 `host` 与外界交互，拿不到 `ipc`、`store`、React 内部对象。

```ts
interface HostApi {
  readonly pluginId: string;
  readonly hostVersion: string;

  /** 调用白名单内的 Tauri IPC 命令（按 manifest 权限校验，越权抛错） */
  invoke<T>(cmd: string, args?: Record<string, unknown>): Promise<T>;

  session: {
    list(): Promise<SessionInfo[]>;              // 仅元数据，不含凭据
    write(id: string, data: string): Promise<void>;   // 需 session.write
    onOutput(id: string, cb: (chunk: string) => void): Disposable; // 需 session.read
    onExit(id: string, cb: (code: number) => void): Disposable;
  };

  ui: {
    registerPanel(id: string, render: () => ReactNode): Disposable; // ui.panel
    registerCommand(id: string, run: () => void): Disposable;        // ui.command
    registerSetting(id: string, render: () => ReactNode): Disposable;
    setStatusBar(id: string, text: string): Disposable;
    toast(msg: string, kind?: "info" | "error"): void;              // ui.toast
    confirm(msg: string): Promise<boolean>;
    openDialog(opts: { directory?: boolean }): Promise<string | null>; // dialog.open
  };

  storage: {
    get<T>(key: string): Promise<T | null>;   // 插件私有命名空间
    set(key: string, value: unknown): Promise<void>;
    remove(key: string): Promise<void>;
  };

  /** 受限网络：需 net.fetch + 域名白名单，默认无此能力 */
  fetch?(url: string, init?: RequestInit): Promise<Response>;
}
```

### 5.1 权限枚举

| 权限 | 说明 | 默认 |
|---|---|---|
| `ipc.<cmd>` | 逐个 IPC 命令授权，未声明即拒绝 | 无 |
| `ui.panel` / `ui.command` / `ui.setting` / `ui.toast` | UI 贡献点 | 无 |
| `session.read` / `session.write` | 读取会话输出 / 向会话写入 | 无 |
| `dialog.open` | 打开系统文件/目录选择框 | 无 |
| `storage.local` | 插件私有本地存储 | 无 |
| `net.fetch` | 受限网络请求（需同时提供 `netDomains`） | **无** |
| `secrets.*` | 密钥环 | **永不授予，硬编码拒绝** |

### 5.2 安全红线

1. **密钥环（SSH 密码 / 私钥口令）任何插件都不可访问**，Host API 不暴露任何读取接口。
2. 插件拿不到 `SftpRequest` 里的凭据原文——凭据由核心从密钥环取出后自行填充，插件只传递档案引用。
3. `net.fetch` 必须同时声明 `netDomains`，非白名单域名直接拒绝并在插件管理中记录。
4. 每次越权调用记一条审计日志，用户可在插件管理中查看「该插件调用过哪些能力」。

## 6. 安装与分发

### 6.1 包格式 `.tpk`
本质是 zip：`termone.plugin.json` + `index.js`（+ 资源）。单包建议 ≤ 2MB。

### 6.2 三种来源
| 来源 | 路径 | 场景 |
|---|---|---|
| 插件市场 | 官方 registry：`GET /index.json` → 插件元数据 + 下载地址 + sha256 | 常规用户 |
| 本地导入 | 选择 `.tpk` 或目录 | 离线 / 内网 / 第三方 |
| 开发者模式 | 指定本地目录，`activate` 热重载 | 自研插件 |

### 6.3 存储布局
```
<app_data>/
  plugins/
    index.json                 # 已安装清单（id/version/enabled/source）
    com.termone.sftp/
      termone.plugin.json
      index.js
      icon.svg
  plugin-data/
    com.termone.sftp/          # 插件私有存储（storage.local）
```

## 7. 工程落地位置

```
apps/desktop/src/
  plugin/
    types.ts        # PluginManifest / PluginInstance / HostApi / Disposable
    hostApi.ts      # createHostApi(manifest)：权限校验 + IPC 白名单
    registry.ts     # 面板/命令/设置/状态栏 的注册与注销
    loader.ts       # 动态 import + 错误边界 + 超时
    manager.ts      # 安装/启用/停用/更新/卸载（调 IPC 落盘）
    sandbox.ts      # 权限枚举、域名白名单、审计日志
  plugins/          # 随包分发的官方插件（默认关闭）
    sftp/  ai-assist/  session-log/  …
  components/PluginManagerDialog.tsx
crates/term-core/src/storage.rs   # 新增 plugins 表（id/version/enabled/source/permissions）
apps/desktop/src-tauri/src/commands.rs  # plugin_install/list/set_enabled/uninstall
```

**构建要求**：插件入口必须走 `import()` 动态导入，产物是独立 chunk，**不进主 bundle**。Vite 需保证 `plugins/**` 单独分包。

## 9. 验收标准

| # | 场景 | 期望 |
|---|---|---|
| AC-1 | 未启用任何插件 | 冷启动耗时与常驻内存相较无插件版本差异 ≤ 5% |
| AC-2 | 主 bundle 产物 | 不含任何插件代码；SFTP 相关代码出现在独立 chunk |
| AC-3 | 插件渲染时抛异常 | 错误边界捕获，显示「插件出错」占位；主窗口与其他插件正常，会话不中断 |
| AC-4 | 插件声明外调用 IPC | 直接抛权限错误，并记一条审计日志 |
| AC-5 | 插件尝试读取密钥环 | 无接口可用；静态检查亦不得出现 `secrets` 相关调用 |
| AC-6 | 停用插件 | 面板、命令、快捷键、设置项、事件订阅、定时器全部注销，无残留 |
| AC-7 | 卸载插件 | 目录、记录、私有存储一并清除 |
| AC-8 | 安装第三方插件 | 弹出权限清单与风险提示，用户确认后方可安装 |
| AC-9 | AI 插件未配置 API Key | 插件置灰不可用，不发起任何网络请求 |

## 11. 已知约束

- 插件**只能调用核心已暴露的 IPC 命令**。若某插件需要新的后端能力，须先在核心补命令并明确权限名——这是刻意设计的闸门，避免插件任意扩张后端攻击面。
- 本机开发机受 **Smart App Control** 管控，`cargo build` 无法运行 build-script（详见 `requirement-coverage.md` RK-08）。插件化的价值在此尤为明显：**S1 与 S2 均为纯前端改动，无需重编 Rust**，本机可直接 `tsc`/`vite` 验证。
- 插件市场为可选能力（S3）；即便没有市场，本地导入 `.tpk` 也能完整闭环，内网用户不受影响。
