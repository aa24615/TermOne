# TermOne 扩展系统设计：插件与应用

> 实现版 v1.1，2026-10-27。需求编号、验收证据见 [覆盖矩阵](./requirement-coverage.md)。

## 1. 运行边界

主窗口保留终端、档案、分组、分屏、最近会话、同步、凭据和基础设置。7 个官方插件、3 个官方应用默认未安装；插件需启用，应用安装后点击图标即可打开，代码通过动态 `import()` 单独分块；插件管理本身也懒加载。

**插件附加主窗口，应用使用独立窗口。** SFTP、AI 辅助、历史日志回放归为应用；其余 7 项依赖主窗口终端或窗口行为，保留插件形态。侧边栏分别提供「插件管理」「应用管理」，主窗口顶部插件入口只列插件；应用通过「应用」入口启动。

应用页面使用独立入口、React 树、状态与 Host，不执行主窗口初始化，不创建终端，不初始化账号同步或其他插件。重复打开聚焦同一应用窗口；关闭应用不关闭主终端。主窗口销毁时回收终端和全局快捷键，已打开的应用可继续使用。后台已经接受的原生文件操作可能完成，其回调不会转移到主终端。

内置扩展是随应用编译、经代码审查的 React 模块；从目录、`.tpk`、registry 导入的代码全部作为第三方运行，不能通过声明 `official` 或冒用官方 ID 获得内置模块执行权。官方目录以 Rust 内嵌的 catalog 为准。

第三方 ESM 在不透明来源的 sandbox iframe 内创建的 Worker 中执行。Worker 无 DOM、无 Tauri、无宿主 React 对象；CSP 禁止直接网络、外部脚本和导航。UI 使用宿主渲染的声明式节点，禁止 HTML。RPC 检查消息来源、随机 token、方法白名单、权限和配额。第三方的固定循环只阻塞自己的 Worker；错误或 5 秒启动超时后终止 Worker。

## 2. Manifest 和包

实际类型以 `src/plugin/types.ts` 与 `term-core/src/plugin.rs` 为准：

```json
{
  "id": "org.example.hello",
  "name": "Hello 插件示例",
  "kind": "plugin",
  "description": "离线插件示例",
  "author": "Example",
  "version": "1.0.0",
  "entry": "index.js",
  "hostApi": { "major": 1, "minor": 0, "patch": 0 },
  "permissions": [{ "type": "ui-panel" }, { "type": "ui-toast" }],
  "files": ["index.js"]
}
```

`kind` 为 `plugin` / `app`；旧包省略该字段时默认为插件。应用必须声明 Host API 1.1.0 或以上，且不能声明 session-read/session-write/event-subscribe/global-shortcut；原生 IPC 绑定真实窗口标签，应用只能使用自己窗口中的 Host。官方旧安装只迁移类型和 Host API 版本，不改变权限、路径授权或私有数据。应用忽略旧 enabled 标记，原生调用仍检查安装记录、权限和窗口归属；插件继续检查启用状态。为兼容旧数据，返回结构中的 enabled 字段仍保留。

入口必须为独立 ESM；可用构建工具把依赖打进入口。资源作为 base64 `assets` 提供。`.tpk` 是包含 `termone.plugin.json` 的 ZIP；支持目录导入、开发目录热加载。

限制：压缩包 4 MiB；展开 16 MiB、256 文件；拒绝绝对路径、`..`、重复 ZIP 路径、反斜杠、Windows ADS、符号链接和本地授权保留文件名。目录遍历深度上限 32。开发模式每 1.5 秒检查代码和资源；manifest 改变须重新导入并确认权限。

```sh
npm run plugin:pack -- examples/hello-plugin target/plugins/org.example.hello-1.0.0.tpk
npm run plugin:pack -- examples/hello-app target/plugins/org.example.hello-app-1.0.0.tpk
```

## 3. 生命周期与存储

插件：安装 → 默认停用 → 用户启用 → 打开时激活 → 停用 / 更新 / 卸载。应用：安装并确认权限 → 点击图标打开 → 关闭窗口 / 更新 / 卸载，无启用、停用状态。历史命令、Triggers、Quake、Zmodem 是用户启用后即激活的后台适配器，其余插件打开面板才加载，应用打开独立窗口才加载。更新重新展示权限；插件恢复为停用，应用更新后点击图标即可再次打开。

停用触发 AbortController：撤销网络请求、等待中的确认框、定时器、事件监听、贡献点和全局快捷键；关闭第三方面板终止 Worker。更新、卸载应用会关闭对应窗口；扩展变更事件刷新主窗口列表。卸载还删除包和私有存储。ESM 模块缓存由 WebView 管理，停用不承诺立即回收已解析代码，承诺回收活动资源。

本地目录：

```text
<app_data>/plugins/<id>/approval.json  # 本机 manifest、启用状态、文件授权
<app_data>/plugins/<id>/index.js ...   # 导入的第三方文件
<app_data>/plugins/audit.jsonl         # 本机审计，512 KB 轮换
<app_data>/plugin-data/<id>/<key>.json # 插件私有数据
```

为兼容已有数据，应用与插件共用原有 `plugins` 表、包目录和私有存储命名空间，类型保存在 manifest，不重复复制数据。SQLite `plugins` 表只同步安装元数据，不同步代码、本机授权或私有数据；远端同步记录无法授予代码执行权。私有存储上限每项 1 MB、每插件 64 项 / 8 MiB。

## 4. Host API v1.1

第三方入口：

```js
export async function activate({ host, manifest, assets }) {
  host.ui.render({ type: 'column', children: [
    { type: 'text', text: manifest.name },
    { type: 'button', text: '通知', onClick: () => host.toast('Hello') }
  ] });
}
```

支持 `text/pre/input/textarea/button/column/row`，回调经 RPC 返回 Worker。`host.ui.registerPanel/registerCommand/registerSetting/setStatusBar` 注册的贡献点带扩展命名空间，可返回注销函数。单插件上限 32 个贡献点；命令面板快捷键 Alt+Shift+P。

权限以对象声明：

- `ipc` + `command`：逐命令白名单，后端再次检查。可用命令为 SFTP 6 项、`profile_refs`、本地 list/mkdir、日志 list/read、Snippets CRUD、theme_install。
- `ui-panel/ui-command/ui-setting/ui-toast`：面板、命令、设置、通知。
- `storage/event-subscribe/session-read/session-write`：私有存储、会话事件、输出订阅、输入。会话元数据不含凭据。以上会话能力仅限插件；应用的会话列表为空，不能订阅或发送主窗口输入。第三方插件写入只允许活动的远端 SSH，会话原生对象和字节写入仅向内置协议适配器开放。
- `dialog-open`：系统文件选择器授予所选路径；本地 list/mkdir、SFTP 上传/下载的本地路径必须位于授权目录。停用即清除路径授权。密钥目录、Keychain、应用私有数据和已配置身份文件不能授权。
- `net` + `domain`：仅精确 HTTPS 域名，不含子域、URL 凭据、重定向或浏览器 Cookie。新增域名需用户明确确认并重新启用插件。
- `global-shortcut`：当前仅内置 Quake 适配器可使用原生注册命令。

任何密钥环、原始档案配置、任意文件读写、任意进程执行命令均不提供给第三方。SFTP 只接收 profileId，核心自行读取密钥环。SSH 禁用本地逃逸序列 `-e none`。本机用户本身有权修改文件，因此本地包/授权文件的 OS 访问权限仍是信任边界。

审计记录插件 ID、动作、时间、允许/拒绝，避免记录参数、口令和终端内容；插件管理可直接查看。消息每秒 200 条、每条 250 KB，Host 订阅上限 64、活动资源上限 128；原生能力调用每插件最多 4 项、全局最多 32 项并发；网络响应流式限制 2 MB。未知 IPC、域名、秘密命令和文件越界记录拒绝。

## 5. 分发

两类管理页共提供 10 个官方模块条目（7 插件 / 3 应用），插件安装不自动启用，应用使用图标网格，安装后点击直接打开。第三方 `.tpk`、目录、开发目录均须展示权限并确认。支持用户自己的 HTTPS registry：

```json
[{
  "id": "org.example.hello-app",
  "name": "Hello 应用",
  "kind": "app",
  "version": "1.0.0",
  "url": "https://plugins.example.com/hello-app-1.0.0.tpk",
  "sha256": "填写包的64位十六进制SHA256"
}]
```

下载包须校验 SHA-256 且 manifest 的 ID、版本、类型与索引匹配。内置目录随应用版本更新；没有部署公共 registry 服务，不宣称已有在线第三方生态。包摘要防下载损坏和索引/包错配，不等于作者签名。

## 6. 官方模块

- 应用 `com.termone.sftp`：本地/远端双栏、拖拽双向传输、队列、失败重试。下载先写 `.part` 再原子替换，上传使用远端临时文件再重命名。
- `com.termone.command-history`：已提交命令记录、完全相同命令去重、最近使用排序、使用次数、搜索、复制和清空。启用后后台记录，关闭面板继续；停用撤销订阅。`history_add/recent/clear` 仅向这个内置插件开放，第三方不能通过冒用 ID 获得访问权。仅本机 SQLite，不进入同步/备份；不抓取隐藏输入、全屏程序或串口输入。
- `com.termone.snippets`：新增、修改、删除、同步，执行前选择会话并确认。
- 应用 `com.termone.session-log`：日志列表、搜索、回放、导出；录制设置留核心，文件使用真实会话 UUID。
- `com.termone.broadcast`：选择多个活动会话，确认内容后发送，可选回车。
- 应用 `com.termone.ai-assist`：兼容 Chat Completions 的 API，用户填写地址、模型和 Key；只发送手动填入的问题，发送前确认，不读取终端、不执行回答，Key 只在面板内存。请求结构参照 [OpenAI 官方接口](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。
- `com.termone.theme-market`：精选主题、JSON 导入、自托管 HTTPS 主题索引；基础主题导入仍在核心设置。
- `com.termone.quake`：可配置全局快捷键，呼出/隐藏主窗口。Linux Wayland 可能限制全局热键。
- `com.termone.triggers`：连接/输出文字匹配、通知/固定命令、冷却和每会话单次限制；命令动作须单独确认后布防，不运行任意 JS。
- `com.termone.zmodem`：Zmodem 双向传输、Sixel 解码；传输需确认，单文件 64 MiB，图片存储 16 MiB。停用卸载终端适配器。

## 7. 验收边界

自动化命令、真机交互、包构建与尚缺的跨设备验证分别记录在覆盖矩阵。独立 chunk 已验证；零插件启动/RSS ≤5% 的严格同环境对照仍需测量，不能用 bundle 大小替代。macOS 本机和 Linux ARM64 容器构建不替代 Windows/其他 Linux 桌面实机验证。


## 8. 工程位置

- `src/applications/`：独立应用入口与 SFTP / AI / 日志模块。
- `src/plugins/`：附加主窗口的 7 项插件。
- `src/plugin/`：共享的受限 Host、安装分发、类型与运行时；内部历史路径名保留兼容。
- `src-tauri/src/applications.rs`：原生应用窗口创建、聚焦与关闭。
- `examples/hello-app`：第三方独立应用的最小 Worker 示例。
