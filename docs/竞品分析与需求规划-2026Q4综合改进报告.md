## 一、执行摘要

### 1.1 一句话结论

TermOne 在 **「轻量 + 隐私 + 自托管 + 开源 + 插件不膨胀」** 这一组合上，仍显著区别于所有主流竞品；但竞品在 **AI 原生融合、本地/云端监控、移动可达、团队共享、协议广度（RDP/VNC）** 上正快速拉齐，且 **Warp 于 2026-04 开源（AGPL v3）、XTerminal 在国内快速起量**，使「开源」与「中文体验」不再只是 TermOne 的独占卖点。下一步的战略不是追着竞品加功能，而是 **把已有护城河从「主张」变成「证据」，并用 Web + 自托管插件正面接住竞品的攻势**。

### 1.2 本次刷新发现的三个关键变量（相对 2026-10-26）

| 变量 | 事实（检索 2026-10-26） | 对 TermOne 的含义 |

### 2.2 已落地但尚缺「验收证据」的能力（风险红线）

> 来源：`requirement-coverage.md` 第八节「构建与验收限制」。**实现完成 ≠ 全设备验收完成**，以下缺口是 IR-01 性能门禁要补的核心。

- 真实 AI 服务/Key、真实远端 Zmodem/Sixel 互通

### 2.3 能力基线小结

TermOne 的「基本盘」（连得上、敲得顺、看得清、私密、可同步）已经闭环且被测试覆盖；增值能力已通过插件/应用架构 **与轻量定位解耦**。真正的短木板不在「有没有」，而在 **（1）护城河证据化不足、（2）AI/监控/移动可达/团队共享的体验落差、（3）切换摩擦仍偏高**。

### 3.2 各竞品优劣势（要点）

- **Warp**：优势＝AI 原生融合、Blocks、团队协作、开源后社区信任；劣势＝重、云端/Agent 依赖、隐私靠「政策承诺」而非「架构可验证」、无原生 SFTP/监控。**TermOne 对策**：不追云端 Agent，强调「架构级本地优先」。
- **XTerminal**：优势＝原生中文、免费、AI+监控+RDP/VNC+MCP 打包、颜值；劣势＝**云端存凭据 + 闭源 + 订阅风险**、监控轻量（仅当前会话、无历史留存）、大文件偏慢。**TermOne 对策**：用「自托管/密钥环永不上传 + 开源 + 本地监控」正面切。
- **Termius**：优势＝移动端全平台、团队 Vault、合规（SOC2/SSO）、生态集成（AWS/Azure/Ansible）；劣势＝云同步付费、团队按席位贵。**TermOne 对策**：用「自托管团队库（IR-06）+ Web SSH（IR-03）」覆盖移动可达与团队共享，且零订阅。
- **Tabby**：优势＝MIT 开源、可配置、插件生态；劣势＝**明确不轻量（Electron ~161MB）**、生态小。**TermOne 对策**：以「轻量 + 原生（Tauri/Rust）」为对照锚点。
- **WindTerm**：优势＝**极轻（~27MB）、秒启、低延迟、中文原生、Sysmon 监控、批量/触发**；劣势＝部分开源、维护节奏不确定、无移动端、UI 偏专业。**TermOne 对策**：WindTerm 是「轻量」主张的最硬 benchmark，IR-01 必须以它为对照。
- **MobaXterm**：优势＝Windows 一站式（X11+RDP/VNC+Unix 命令）、便携单 exe；劣势＝仅 Windows、界面密集、Home 限额。**TermOne 对策**：跨平台是 TermOne 的相对优势，但 X11/Windows 管理员细分不做。
- **electerm**：优势＝免费开源、协议最广（含 RDP/VNC/Spice）、移动端、AI+MCP、云同步多路径；劣势＝个人导向、团队弱、Electron 偏重。**TermOne 对策**：AI+MCP 趋势需回应（IR-05/IR-10），但用「插件不膨胀」保持轻量。

## 五、差距分析与护城河判定

### 5.1 护城河（必须守住，不可为短期功能妥协）

1. **轻量 + 隐私 + 自托管 + 开源 + 插件不膨胀** 这一组合，目前 **无任何竞品同时具备**。这是 TermOne 的「不可能被快速复制」区。
2. 守住的代价：任何新功能都必须过 IR-01 性能门禁与 R-20 权限/隔离红线——**功能膨胀是头号风险（历史评估 RK-02 高）**。

## 六、改进方向（总览）

**战略主轴（一句话）**：护城河从「主张」变「证据」，用「Web + 自托管插件」正面接住竞品攻势，AI 守隐私红线不跟随。

1. **自证轻量**：公开量测 + 与 WindTerm/Tabby/XTerminal 同机对比（IR-01）。
2. **守住中文基本盘**：本地化审计 + 默认简体中文（IR-02）。
3. **用 Web 补移动可达**：Web 加 SFTP + 多标签（IR-03），绕开原生移动端 Won't。
4. **本地监控不传云**：对标 XTerminal 监控但全程本地（IR-04）。
5. **AI 差异化 = 可证明的隐私**：默认用户自有端点、零数据出本机可验证（IR-05）。
6. **自托管团队库**：切 Termius 团队收费（IR-06）。
7. **降低切换摩擦**：增 XTerminal/electerm 导入（IR-09）。
8. **生态前瞻**：MCP 可插拔（IR-10）、快速命令/动态变量（IR-07）、转发可视化（IR-08）、断点续传（IR-11）、笔记（IR-12）。

## 七、具体改进建议（优先级 + 预期价值）

> 编号说明：IR = Improvement Recommendation（改进建议），为下一规划周期提案，评审通过后并入 `需求.md` 正式编号。每项含：描述、业务规则、优先级（MoSCoW）、预期价值、验收标准、版本归属、关联历史需求。

### IR-01 零插件性能门禁 + 公开基准（深化 R-22/R-23）　【Must】

- **描述**：在 CI 与发布流程固化「零插件冷启动耗时、常驻 RSS、安装包体积」三项门禁（阈值：相对无插件基线差异 ≤5%）；并产出一份公开基准报告，与 WindTerm（~27MB）、Tabby（~161MB）、XTerminal（~139MB）同机对比。
- **业务规则**：未启用任何插件/应用时，冷启动、RSS、体积不得高于无插件版本 5%；每次发版自动跑并归档；报告含机型/系统/版本。
- **预期价值**：把「轻量」从口号变证据，直接对冲 WindTerm 的轻量 benchmark 与 Tabby 的「不轻量」自承；是护城河防御的基石。
- **验收标准**：CI 产物含三项指标；任一超阈值阻断发版；公开基准页可访问且含三方对照。
- **版本**：v0.6（护城河加固）
- **关联**：R-22、R-23

### IR-02 中文本地化完成度审计 + 默认简体中文（深化 R-39）　【Must】

- **描述**：全量 UI 字符串提取审计，补遗漏文案；安装首启默认 `zh-CN`（保留系统跟随/英文切换）。
- **业务规则**：所有面向用户文案须有中文；设置项、错误提示、空/错/加载态均覆盖；不引入机器翻译味浓的措辞。
- **预期价值**：XTerminal 的本营是中文用户；本地化完成度直接决定国内第一印象与留存。
- **验收标准**：审计表 100% 覆盖；默认 zh-CN 首启验证；英文切换无缺字。
- **版本**：v0.6
- **关联**：R-39

### IR-03 Web SSH 增加 SFTP + 多标签/分屏（深化 R-27/R-28）　【Should】

- **描述**：Web 端在现有 SSH 网关上增加文件管理（复用桌面 SFTP 的核心 IPC，服务端代理 ssh2-sftp）；并支持多标签与基础分屏。
- **业务规则**：Web SFTP 沿用「凭据默认不上传、勾选才 AES-256-GCM 落盘」模型；大文件走分块；保持 JWT/TOFU 边界；E2EE 主机在 Web 端继续禁连并提示。
- **预期价值**：用 Web 绕开原生移动端 Won't（R-18），承接「手机/平板上不仅要连、还要传文件」的高频紧急场景，正面回应 Termius/electerm 的移动可达优势。
- **验收标准**：Web 端登录后可在主机上列出/上传/下载/编辑文件；多标签切换无串会话；移动浏览器可操作。
- **版本**：v0.7
- **关联**：R-27、R-28、R-21

### IR-04 本地服务器监控面板（深化 R-37）　【Should】

- **描述**：以插件/应用形态提供轻量监控：通过 SSH 执行本地采集命令（如 `top`/`free`/`df`/`cat /proc`），在面板画 CPU/内存/磁盘/网络折线；可选历史落本地库。
- **业务规则**：**全程本地、不上传任何指标到第三方**；采集命令白名单 + 频率可配；超出主窗口轻量预算，必须走扩展（不进主窗口）；失败降级为「手动命令」。
- **预期价值**：对标 XTerminal 监控，但用「本地 + 开源 + 不传云」切其「云存 + 闭源」信任软肋；满足国内运维一眼看资源的高频需求。
- **验收标准**：面板显示 4 项指标实时图；可配置刷新频率；关闭应用不影响终端；明确标注「数据仅留本机」。
- **版本**：v0.7
- **关联**：R-37

### IR-05 AI 助手隐私优先 + 报错解释/上下文补全（深化 R-12/R-34/R-41）　【Should】

- **描述**：AI 应用升级：① 默认用户自有 OpenAI 兼容端点，Key 仅内存；②「解释报错」一键把选中 Block + cwd + 命令发给模型；③ 上下文感知补全建议（Next Command 思路）。所有出站数据在 UI 显式提示「将发往你配置的端点」。
- **业务规则**：**绝不预置任何第三方云端 Key 或默认上报**；提供「纯本地模式」关闭所有网络；与用户自有端点交互仍受 R-20 网络白名单约束；不读终端之外数据。
- **预期价值**：AI 已成标配，TermOne 的差异化是「可证明的隐私」——竞品（尤其 XTerminal/electerm）把命令内容发自己云，TermOne 把控制权交还用户。
- **验收标准**：默认无第三方端点；解释报错返回可读建议；网络白名单仅含用户配置域名；隐私声明在界面可见。
- **版本**：v0.7
- **关联**：R-12、R-34、R-41

### IR-06 自托管团队库 / 共享 Vault（深化 R-40）　【Should】

- **描述**：在自托管服务端增加「组织/团队」概念：管理员建团队、邀请成员、共享主机档案（凭据按策略：仅管理员持有或成员各自保存）；支持角色（管理员/成员）与数据权限隔离。
- **业务规则**：凭据共享遵循「密钥环/服务端加密」既有红线；成员退出即撤销可见性；复用现有 `user_items`/同步协议，避免重写；自托管，无订阅。
- **预期价值**：切 Termius Team（$20·人·月）/ Business（$30·人·月）的高按席位收费，提供零成本自托管替代，打开「小团队/公司内网」市场。
- **验收标准**：团队创建/邀请/共享档案可用；成员权限隔离正确；退出后不可见；与桌面/Web 同步兼容。
- **版本**：v0.8
- **关联**：R-40、R-29

### IR-07 快速命令 + 动态变量（深化 R-07 Snippets）　【Should】

- **描述**：在 Snippets 插件上升级为「快速命令」：支持参数占位符（如 `{{host}}`/`{{path}}`）、默认值、按主机/分组作用域；一条命令适配多场景，一键执行或填充到终端。
- **业务规则**：变量在执行前在确认框显式展开预览；危险命令仍走 R-26 检查；变更参与同步。
- **预期价值**：对标 XTerminal 快捷命令、WindTerm 一键命令；降低重复操作与出错，提升日活留存。
- **验收标准**：带变量的快速命令可参数化执行；预览正确；与 Snippets 数据兼容。
- **版本**：v0.7
- **关联**：R-07

### IR-08 端口转发可视化状态面板（深化 R-06）　【Could/Should】

- **描述**：在转发/跳板能力上增加可视化面板：列出活动隧道（本地/远程/动态）、映射端口、连接数、启停控制。
- **业务规则**：仅展示本机建立的隧道，不主动探测远端；轻量，可为主窗口侧栏或插件。
- **预期价值**：对标 XTerminal「转发可视化管理」，降低运维心智负担；成本低。
- **验收标准**：面板显示当前隧道与端口；可启停；与 -L/-R/-D/-J 配置一致。
- **版本**：v0.7
- **关联**：R-06、R-10

### IR-09 导入向导增加 XTerminal / electerm 配置导入　【Should】

- **描述**：在跨软件导入（已支持 20+ 来源）新增 XTerminal 导出、electerm 全量/书签 JSON 的专用解析与预览。
- **业务规则**：密码不迁移、私钥仅路径；不执行任何命令；重复跳过；与现有导入事务一致。
- **预期价值**：直接降低从最热国产竞品（XTerminal）与开源竞品（electerm）迁移的摩擦；低成本高杠杆获客。
- **验收标准**：XTerminal/electerm 导出可解析、预览、选择性导入；测试覆盖。
- **版本**：v0.6
- **关联**：跨软件导入（已有）

### IR-10 MCP 客户端可插拔（前瞻）　【Could】

- **描述**：AI 应用支持接入本地 MCP Server（用户自配置），使 AI 可调用本地工具（读文件、受限命令）。默认关闭、本地优先、不强制云端。
- **业务规则**：MCP 调用受 R-20 网络/权限约束；任何工具执行需用户确认；不暴露密钥环。
- **预期价值**：对标 XTerminal v5.8.6、Warp、electerm 的 MCP 趋势；保持「AI 也守隐私」的一致性。
- **验收标准**：可配置本地 MCP Server 并成功调用一个工具；越权被拒；默认关闭。
- **版本**：v0.9（前瞻）
- **关联**：R-12、IR-05

### IR-11 SFTP 断点续传 + 大文件优化　【Should】

- **描述**：SFTP 应用在传输中断时支持断点续传；大文件分块并行/校验；失败重试只补差额。
- **业务规则**：远端旧文件不被半文件覆盖（沿用 `.part` 策略）；保留失败回滚；与现有 sftp-smoke 对齐。
- **预期价值**：补 XTerminal「大文件偏慢」、MobaXterm 大文件弱项，建立「可靠传输」口碑。
- **验收标准**：中断后续传字节一致；大文件（≥1GB 估算）可完成；重试不损坏。
- **版本**：v0.7
- **关联**：R-01

### IR-12 笔记 / 运维备忘（插件）　【Could】

- **描述**：按主机/分组关联的 Markdown 笔记，记录运维信息；本地存储，可选随同步（E2EE）。
- **业务规则**：仅本地/自托管，不上第三方；不混入命令历史同步。
- **预期价值**：对标 XTerminal 笔记、Termius；轻量增值，留住高频运维用户。
- **验收标准**：笔记与主机关联、可编辑、可检索；可选加密同步。
- **版本**：v0.8

### IR-13 RDP / VNC 协议支持　【Won't（本期）/ 后续评估】

- **描述**：是否支持图形远程（RDP/VNC/Spice）。
- **决策**：**本期不做**。理由：与「轻量 + SSH/terminal 定位」冲突，引入新原生依赖与体积；XTerminal/MobaXterm/electerm 已覆盖且 TermOne 差异化不在此。列为后续版本候选，需重新评估轻量预算与优先级。
- **关联**：定位（需求.md 2.1 一刀切标准）

### IR-14 原生移动端 App　【Won't（维持）】

- **描述**：是否开发 iOS/Android 原生 App。
- **决策**：**维持 Won't（R-18）**。以 Web SSH（IR-03 加 SFTP/分屏）覆盖移动可达，避免双端原生维护成本；如 Web 体验达标则不再投入原生。
- **关联**：R-18、R-21、IR-03
