## 二、核心定位（新增）

**主窗口只做一件事：连得上、敲得顺、看得清。**

任何「不是每个用户、每次打开都用」的能力，**一律不做进主窗口**，改为官方插件按需安装。

### 2.1 一刀切判定标准

满足任一条件即**必须插件化**（一票否决）：

1. 会显著增加冷启动耗时、常驻内存或安装包体积；
2. 覆盖的用户场景 < 50%（不是人人天天用）；
3. 需要联网调用外部服务（如 AI、主题市场）；
4. 需要引入新的原生依赖或平台特有实现；
5. 存在隐私争议、需要用户额外授权才能放心使用。

### 2.2 主窗口保留（内置核心，不可插件化）

| 能力 | 保留理由 |
|---|---|
| 本地终端 / SSH / 串口会话 | 基本盘，人人必用 |
| 多标签页 + 分屏 | 高频、纯 UI、开销极低 |
| 连接档案 / 分组 / 搜索 / 最近会话 | 基本盘 |
| 本地 SQLite + 云同步备份 | 基本盘 |
| 密钥环（凭据永不入库、永不上传） | 隐私底线，**插件绝对不可触碰** |
| 主题 / 字体 / 基础设置 | 轻量 |
| **插件运行时 + 插件管理** | 承载一切增值能力的地基 |

### 2.3 一律插件化（不进主窗口）

| 能力 | 插件形态 |
|---|---|
| **SFTP 图形化文件管理** | 官方插件 `com.termone.sftp` |
| **AI 命令辅助** | 官方插件 `com.termone.ai-assist`（默认关闭） |
| 广播输入（多窗格同发） | 官方插件 `com.termone.broadcast` |
| 会话日志回放 | 官方插件 `com.termone.session-log`（录制开关留核心） |
| 常用命令 Snippets | 官方插件 `com.termone.snippets` |
| Zmodem / Sixel 图片预览 | 插件 `com.termone.zmodem` |
| Quake 模式 / 全局热键 | 插件 `com.termone.quake` |
| Triggers / 自动化 | 插件 `com.termone.triggers` |
| 主题市场 | 插件 `com.termone.theme-market`（核心只保留主题导入） |

## 三、插件系统需求（新增，Must）

### 3.1 形态：前端插件为主

- 插件是 **JS/TS 包**，官方内置模块由主窗口 `import()` **动态懒加载**，不进主 chunk；本地/市场第三方代码在隔离 Worker 中运行，通过声明式 UI 与受限 Host API 交互。
- 插件通过**受限 Host API** 调用已存在的 Tauri IPC 命令，**零新增原生依赖**、跨平台免编译、即装即用。
- 核心保留少量高频 / 涉密的后端 IPC 命令（例如 SFTP 的 6 个命令），插件只承载 UI 与交互逻辑。
  > 这样插件迭代**不需要重新编译 Rust**，也不受本机打包环境限制。

### 3.2 安装方式（三种都要有）

1. **插件市场**：内置官方插件目录，一键安装 / 更新；支持自托管 HTTPS registry（下载摘要校验）。公共 registry 服务部署不在本地客户端实现范围。
2. **本地导入**：`.tpk` 包（zip）或目录，支持离线、内网环境。
3. **开发者模式**：指向本地目录，改动热加载，便于自研插件。

### 3.3 生命周期

`安装 → 启用 → 激活（按需懒加载）→ 停用 → 更新 → 卸载`

- 插件默认**不启用**，由用户显式开启，绝不在后台偷偷加载。
- 停用 / 卸载后必须彻底注销：面板、命令、快捷键、设置项、事件订阅、定时器全部清理干净。

### 3.4 非功能红线（验收硬指标）

| 项 | 要求 |
|---|---|
| 零插件开销 | 未启用任何插件时，冷启动与常驻内存**不得高于无插件版本**（差异 ≤ 5%） |
| 崩溃隔离 | 单个插件崩溃**不得**导致主窗口崩溃或会话中断（错误边界隔离） |
| 权限声明 | 插件必须声明权限，越权调用直接拒绝；**密钥环任何插件都不可访问** |
| 网络白名单 | 插件默认无网络能力；需联网的插件（AI、市场）须显式声明并展示域名清单 |
| 可审计 | 插件的 IPC 调用与权限使用可在插件管理中查看 |

> 完整技术规格见 [`docs/插件系统设计.md`](./插件系统设计.md)。
> 需求编号与版本排期见 [`docs/竞品分析与需求规划.md`](./竞品分析与需求规划.md)。

## 四、Web 版 SSH 远程管理（新增）

> 服务端需要一个 **Web 版**，用于浏览器里做 **SSH 远程管理**。**仅做远程 SSH**——不做本地终端、不做串口。

### 4.1 范围

| 包含 | 不包含 |
|---|---|
| 浏览器连接远程 SSH（密码 / 私钥） | 本地 Shell、WSL、Docker |
| 主机管理（增删改查） | 串口 Serial |
| 终端交互：输入输出、窗口尺寸同步、退出码 | SFTP 文件管理（Web 端后续再说） |
| 登录鉴权（复用现有账号体系） | 多标签 / 分屏（Web 端后续再说） |

### 4.2 关键约束

1. **必须登录**：WebSocket 握手需携带有效 JWT，否则以 `4401` 关闭。绝不能让服务器变成开放 SSH 代理。
2. **密钥默认永不上传**（与桌面端一致的默认策略）：保存主机时**默认只提交元数据**，
   密码 / 私钥不出本机；连接时由客户端临时提交，服务端**用完即弃、不落盘**。
3. **是否上传由用户勾选**：客户端提供勾选项「把凭据加密保存到服务端」，**默认关闭**。
   勾选后才上传并以 **AES-256-GCM** 加密落盘（主密钥独立于数据库）；**取消勾选立即删除**服务端已存的凭据。
4. **可只记在本机**：另提供「在本机浏览器记住凭据」（localStorage），同样**永不上传**，
   侧栏以徽标区分「服务端 / 仅本机 / 未保存」，并支持一键「忘掉」「清除本机凭据」。
5. **接口永不返回明文**：主机列表只返回元数据 + `hasCredential`；编辑时凭据留空表示「保持不变」。
6. **提供临时连接**：不登记主机、两端都不保存，用完即弃——给零知识诉求留出口。
7. **主机公钥 TOFU**：首次连接记录指纹并信任；指纹变更即拒绝，防中间人。
8. 凭据存放位置必须在 README 与 UI 中明示，让用户随时知道「密钥在哪」。
9. **与桌面端共用主机库**：Web 端与桌面端保存的 SSH 主机是**同一份数据**——统一存服务端
   `user_items` 表（`kind='profile'`），与桌面端云同步（`/api/sync/push|pull`）同表、同格式；
   任一端增删改，另一端同步后立即可见；删除以 tombstone 传播。凭据单独存 `ssh_credentials`
   按主机 id 关联。桌面端 agent 认证 / E2EE 加密同步的主机在 Web 端有明确的降级提示（不可连 / 不可编辑）。

### 4.3 技术选型

- 服务端 `ssh2`（纯 JS，零原生依赖）+ `@fastify/websocket` + `@fastify/static`
- 前端新建 `apps/web`（Vite + React + xterm.js），生产由 `apps/server` 托管 `dist`，同源免跨域
- 数据帧用 base64 承载字节流，客户端用流式 `TextDecoder` 解码，避免多字节字符被截断

## 六、R-26 多行粘贴与危险命令确认

桌面端的本地、SSH、串口终端在粘贴前做本机检查，多行或识别到危险模式时展示目标、原因和待发送内容，明确确认后才发送，取消不补发。手工输入在回车前检查；历史记录、补全等无法可靠追踪的编辑额外要求核对。保持 bracketed paste，不额外追加回车；会话退出、检查失败或面板关闭时不得发送待确认输入。

这是误操作提醒，不是完整 shell 解析器；动态变量、别名、交互程序及插件自动化存在各自边界。本节范围为桌面终端。实现与实测证据见覆盖矩阵 R-26。
